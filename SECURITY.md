# Security policy

## Supported versions

Security and robustness fixes are applied to the latest released 0.x version.
Research snapshots and unreleased historical commits are not supported.

## Reporting a vulnerability

Do not open a public issue for a suspected memory-safety vulnerability or a
denial-of-service input. Use GitHub's private vulnerability reporting for the
repository. If that feature is unavailable, contact the maintainer listed in
`pyproject.toml` and include a minimal reproducer, affected version, platform,
and expected impact.

The project aims to acknowledge a report within seven days. No guarantee is
made that RPnP++ is suitable for safety-critical use; see the MIT License's
warranty disclaimer.
